**从一堆材料里挑出相关内容，并且能证明自己没漏、能说明为什么收或不收。**

把材料丢进去，输入关键词。相关度按颜色分级（青绿 = 强相关 → 红 = 无关），
一只数码虫在内容网络里逐条爬行判定，全过程实时可见。跑完之后你会拿到两样东西：
**挑出来的内容**，以及一份**能核对的完整性凭据** ——
"全文 N 个字符，其中 M 个被关键词覆盖；以下 K 个区间从未被碰到"。

面向**不想写代码、但需要为结果负责**的人：分析师、法务、财务、记者、研究助理。

## 这个项目**不是**什么

写清楚这个很重要，免得你装错了期待：

- **不是一个生产级爬虫。** 没有反爬绕过、没有 JS 渲染、没有代理池、没有断点续爬。
  要正经抓网站，用 [Scrapling](https://github.com/D4Vinci/Scrapling) / Scrapy / Crawlee。
  本项目的抓取能力只是"顺带能给个数据来源"，真正的主力是**本地材料**。
- **不做语义理解。** 相关度是**关键词覆盖度**，不是向量检索、不是 LLM 判断。
  它快、可复现、可解释，但不懂同义词。
- **不是通用 ETL。** 输出是给人看的 + 给 Excel 吃的，不是数据管道组件。

它**是**什么：一个把"我到底有没有漏掉东西"这个问题，变成可核对数字的工具。

## 模式一：本地文档（默认）

### 支持格式

| 格式 | 说明 |
|---|---|
| **.docx** | Word 2007+。**零依赖解析**：`.docx` 本质是 ZIP，正文在 `word/document.xml`，用浏览器原生 `DecompressionStream('deflate-raw')` 自己解包 + `DOMParser` 解 XML。 |
| **.md / .markdown** | 标题、段落、`\| --- \|` 表格都会识别 |
| **.txt** | 按空行切段 |
| **.html / .htm** | 取 `h1-h6`、`p`、`li`、`pre`、`table` |
| **.doc** | ❌ 97-2003 老二进制格式，解析不了。会明确提示你另存为 `.docx` |

需要 `DecompressionStream`：Chrome/Edge 80+、Safari 16.4+、Firefox 113+。老浏览器会给出明确提示而不是静默失败。

### 关键词与指令

编辑区写**关键词**，空格或逗号分隔：

```
# 井号开头是注释
财务 营收 增长率 毛利率 用户数
过滤 广告 免责声明 版权所有
表格 财务              ← 可选：只提取含"财务"的表格；不写则全部提取
上限 8                 ← 可选：动画最多呈现 8 处命中（导出仍为全量）
置信度 0.35             ← 可选：命中判定阈值
```

- **关键词** — 每个词在图上是一根从文档中心发散出去的分支。
- **过滤** — 否定清单，命中的位置会被扣分。
- **表格** — 不写就提取文档里**全部**表格；写了词就只收含该词的表格。

### "完整提取"具体意味着什么

这是整个功能的核心承诺，实现上分两阶段：

1. **全量扫描**（无动画）—— 文档里**每一个**内容块都过一遍评分器，命中的全部留下。
2. **动画呈现** —— 只把得分最高的前 N 个做成图节点，让数码虫爬过去。

也就是说 **图是呈现，不是数据**。命中列表、导出文件用的都是第 1 阶段的完整结果，
`上限 8` 只影响动画条数，不会截断你的数据。导出的 `summary` 里会同时给出
`matchesTotal` 与 `matchesAnimated`，你可以自己核对。

**表格的"完整"**指：横向合并（`w:gridSpan`）与纵向合并（`w:vMerge`）都会被还原。
内部同时产出两种形态 —— `grid`（合并区域重复填值，直接给 CSV 用）和
`cells`（带 `rowspan`/`colspan`，给界面渲染用）。

### 表格查看与导出

扫描完成后左侧列表里每个表格都有一张卡片，点 **查看完整表格 ▸** 打开浮层：

- 完整网格渲染，合并单元格用真实 `rowspan`/`colspan` 呈现
- **⤓ 导出此表 CSV** —— 单个表格，纯粹的二维表
- **⧉ 复制到剪贴板** —— 复制为 TSV，可直接粘进 Excel

右下角"导出结果"里还有一项 **表格 CSV**：把所有表格导成一张长表
（`table_index, table_section, row, col, value`），Excel 里可直接透视。

## 模式三：真实抓取

真的发 HTTP 请求、真的解析 HTML、真的抽链接。受 CORS 限制，需要通过"中继"发请求。

真实模式的四种中继（顶栏第二个下拉框）：

| 中继 | 说明 |
|---|---|
| **ALLORIGINS** | 公共 CORS 中继，直连、无需自建。默认项。 |
| **JINA-READER** | 返回 markdown 正文。会从 markdown 链接语法里抽出链接，所以多跳也能跑，但拿不到原始 HTML 结构（表格、`<pre>` 等），正文形态会变。 |
| **本地代理 8787** | 跑 `node proxy.mjs` 后选它。最稳、可控、支持多跳。 |
| **直连 DIRECT** | 目标站点自己带 CORS 头时才可用。 |

### 启用真实抓取

```powershell
node proxy.mjs          # 输出 http://127.0.0.1:8787/?url=<目标>
```

然后顶栏：模式选 **真实抓取** → 中继选 **本地代理 8787** → 提示词里写好 `站点 https://目标站/起始页` → ▶ 启动。

真实模式会遵守这些约束：同源限制（只跟同 host 的链接）、并发上限、每请求 16s 超时、
单页最多取 6 条子链接、深度与页数上限、URL 去重。

## 指令 DSL（三种模式共用）

左边编辑区语法高亮，`Tab` 缩进，`Ctrl+Enter` 运行，`Esc` 中止。
**同一份文本**在三种模式下含义略有不同 —— 本地文件模式读作关键词，另外两种读作采集意图。

```
# 井号开头是注释，不参与采集

抓取 "量子计算" 商业化 落地 金融 制药        ← 采集意图／关键词；引号=高权重短语
提取 文本 数据 代码                          ← 内容类型
过滤 广告 导航 版权 免责声明                 ← 否定清单：命中就扣分，不会当成采集目标
表格 财务                                    ← 本地文件模式：只提取含"财务"的表格
站点 https://example-quantum.io             ← 起始 URL
深度 3                                      ← 最大跳数
上限 36                                     ← 抓取模式=最大页数；文件模式=动画呈现条数
类型 文本,数据,代码                          ← 只生成/保留这些类型
排序 相关度                                  ← 排序策略
去重 标题                                    ← 去重键
置信度 >= 0.45                              ← 低于此分判为 REJECT / 不判定为命中
延迟 260                                    ← 每页间隔 ms（模拟模式）
选择器 "pre > code"                          ← 指定抽取区域
```

指令都支持**省略冒号**（`深度 3` 与 `深度: 3` 等价）。
中文按空格分词，≤6 字的块整体成一个术语（保留可读标签）；超长无空格中文串才退化成 2-gram。

模拟／真实模式内置三套示例：`示例·量子` / `示例·代码` / `示例·市场`。切换模式时，
如果编辑区还是内置示例内容，会自动换成对应模式的默认模板。

```
│ 上传区      │        力导向蛛网网络图            │  3 张悬浮卡片     │
│ 关键词编辑器 │   青绿↔红发光分叉线 · 红底标签节点   │  绿/橙/黄边框     │
│ 行号/位置   │   数码虫沿分支爬行                 │  大号数字         │
│ 抽取内容流  │   数据包飞向分析区                 │  迷你走势 + 遥测  │
├────────────┴──────────────────────────────────┴──────────────────┤
│ 决策日志 │ 置信度折线 │ 相关度点阵热力图 │ 三维散点球 │ 进度条 │ 统计 │
└──────────────────────────────────────────────────────────────────┘
```

三种模式下**图形结构完全一致**，只是节点含义不同：

| | 种子（中心） | 第一层 | 第二层 |
|---|---|---|---|
| **本地文件** | 文档 | 关键词 | 命中的段落／表格 |
| **模拟引擎** | 种子站点 | 合成页面 | 更深一层 |
| **真实抓取** | 种子站点 | 真实网页 | 更深一层 |

面板标题、卡片标题、进度条文字都会随模式自动改写（编辑器标题、`提取到的表格` 卡片等）。

**六个仪表盘各自在看什么：**

1. **DECISION LOG** — 每一页的判定流水：时刻 / 动作（HARVEST·EXTRACT·FILTER·REJECT·ERR）/ 目标 URL / 得分。左侧色条就是判定结果。
2. **CONFIDENCE** — 逐页置信度序列，按相关度渐变着色，虚线是提示词里的 `置信度` 阈值线。
3. **RELEVANCE MATRIX** — 行 = 提示词分支（最多 9 个），列 = 抓取步；点的亮度 = 该分支在该页的命中强度。一眼看出哪个分支在哪些页面上真正生效。
4. **SEMANTIC SPHERE** — 已抓页面投到球面散点上，颜色 = 相关度，靠近正面越大越亮，高分点拉一条到球心的线。转起来看分布。
5. **PIPELINE** — 队列调度 / 请求抓取 / 正文解析 / 相关度评分 / 去重归一 / 归档入库 六段负载。
6. **STATISTICS** — 页数、边数、字节、均值/峰值相关度、命中分支、最大深度、拒绝数、重复数、速率、耗时。

**三张悬浮卡片**：抓取页数（绿）· 平均相关度（橙）· 命中分支数（黄），每张带大号数字、迷你走势和进度条。

**数码虫在做什么？** 它不是一个装饰动画 —— 它就是爬取调度本身。
虫子从种子节点出发，每次挑**优先级最高**的前沿节点爬过去（优先级的排序依据就是相关度预期），
到达后节点亮起、按相关度着色、弹出内容数据包飞向左侧抓取流。
所以你看到的爬行顺序，就是真实的抓取顺序。

## 导出结果

运行结束（或中止/出错）后，**右下角浮出 ⤓ 导出结果 按钮**，点开有四种格式：

| 格式 | 内容 | 用途 |
|---|---|---|
| **Markdown** | 汇总表 + 源文件/提示词 + 分支命中表 + 结果表 + **全部表格还原成 Markdown 表格** + 每条抽取内容 | 直接看 / 贴进报告 |
| **JSON** | 全量结构化：source、config、summary、branches、`tables[]`（含完整 `grid`）、pages[]、decisions[]、confidenceSeries[] | 二次处理 |
| **CSV** | 结果行，列随模式变化（文档模式为 `section,offset,kind,relevance,verdict,branches,content`） | Excel / 表格 |
| **表格 CSV** | **全部表格**导成一张长表：`table_index,table_section,row,col,value` | Excel 透视 / 入库 |

三个实现细节：
- CSV 带 **UTF-8 BOM**，Excel 打开中文不乱码；
- 字段按 RFC 4180 转义（逗号、引号、换行都会被正确包裹）；
- **表格 CSV** 是长表格式 —— 一行一格，`table_index` 区分表、`row`/`col` 定位。
  这样多张不同宽度的表能安全共存于一个文件，Excel 里拉个数据透视就能还原成任意一张表。
  想要"纯粹的"二维表，就在表格查看器里用 **⤓ 导出此表 CSV**。

导出的 `decisions` 是**全量决策记录**（上限 1200 条），不是屏幕上只显示最近 90 条的那个列表。
文档模式下 `pages[]` 也是**全量命中**，不受 `上限 n`（动画呈现条数）影响 ——
`summary` 里同时给出 `matchesTotal` 与 `matchesAnimated` 供你核对。

## 性能与内存

抓到几十页之后开始卡顿，根因是两处**随规模线性恶化**的绘制热点，已经改掉：

| 问题 | 原实现 | 现实现 |
|---|---|---|
| 节点辉光 | 每节点每帧 `createRadialGradient` —— 持续分配对象触发 GC 抖动 | 启动时预渲染 16 档辉光贴图，运行时只做 `drawImage` |
| 发光线条与标签 | 每条连线、每个节点、每个标签各自设一次 `shadowBlur`（Canvas 最贵操作） | 连线按 8 个色档分组，一组一条路径一次 `stroke`；用 1–3 层宽而淡的叠加描边替代阴影 |
| 热力图 / 折线图 | 每帧全量重绘（含 300+ 带阴影的点） | 离屏缓存，只在数据或尺寸变化时重绘；每帧只画扫描列与末端脉冲 |
| 物理仿真 | 每帧 O(n²) 斥力，即使图已收敛 | 收敛后（alpha 低）降为每 3 帧一次 |
| 标签密度 | 固定阈值，节点一多就糊成一片 | 阈值随节点数/画质档位自动抬高 |
| 内存 | 前沿候选与无关节点一直累积 | 有界前沿 + 节点归档回收（每 6 页触发一次） |

自测里锁定了这个修复：**每帧渐变分配与 shadowBlur 调用数必须与节点数无关**。

```
每帧绘制调用   20节点: {grad:1, shadow:1, stroke:23, fill:62,  img:21}
              200节点: {grad:1, shadow:1, stroke:69, fill:115, img:201}
```

渲染压力因此从「节点数 × 昂贵操作」变成「节点数 × 一次贴图 blit + 一次描边」。

**自适应画质**：主循环持续监测平滑帧时，顶栏 `QL` 显示当前档位
（`2` 全效果 / `1` 降级 / `0` 最简）。帧时超过 26ms 自动降档，回到 15.5ms 以下自动升回，
所以你机器慢的时候画面会自己变简单而不是卡死。

**内存回收**：每抓 6 页执行一次 —— 前沿候选只保留优先级最高的 36 个（等价于有界优先队列），
节点超过 80 个后从「已判定无关的叶子」开始归档，先牺牲相关度最低的。
回收时同步清理连线（不留悬空边）、索引、评分序列、数据包与拖尾。
被回收的节点仍计入统计与导出。回收动作会在决策日志里留一条 `GC` 记录，你能看见它发生。

回收有软上限 80 / 硬上限 120，**默认的「上限 36」根本碰不到归档**，图会完整保留；
只有把上限开大（例如 120）时才会启动回收。实测：

```
构造超限图 = 226 节点 / 165 边
pruneGraph → 节点被压回软上限 = 80，前沿 = 36
归档计数 = 146，边数 165 → 43，悬空边 0，索引同步 80
```

## 相关度是怎么算的

`scoreText()` 是唯一的评分器，模拟与真实抓取共用：

1. **分支命中饱和度** — 每个提示词分支在正文/标题里的出现次数经 `log1p(x)/log1p(4)` 压缩，避免堆词刷分。
2. **按权重加权平均** — 引号短语权重 2.2，长词有额外加成，普通词 1.0。
3. **结构加权** — 标题命中 ×1.04，正文 >1200 字 ×1.03，类型匹配 ×1.06。
4. **否定清单惩罚** — `过滤` 行里的词命中比例越高，得分压得越狠（最高 ×0.12）。
5. **轻微噪声** ±3.5%，避免完全线性（实测同输入抖动带宽 0.056）。

得分 → 颜色：`0.00` 红 → `0.50` 黄 → `1.00` 青绿，与图上边线、节点、日志、卡片统一色标。

## 真实抓取的注意事项

- **遵守目标站点的 robots.txt 与服务条款。** 本工具不做 robots 校验，默认同源 + 限量（上限/深度/延迟）访问，请自行确认你有权抓取。
- **公共中继有速率限制**，被限流是常态；稳定的做法是跑 `proxy.mjs`。
- **别把上限开太大**。`上限 36` / `深度 3` 对演示足够；大规模抓取请用专业框架。
- `proxy.mjs` 已做基本 SSRF 防护（DNS 解析后拒绝内网/环回/链路本地地址、限体积、限超时、只监听 127.0.0.1），
  但 redirect 跟随不重新校验目标，**仅适合本机使用**，不要直接暴露到公网。

## 一个必须记住的坑：不要用 PowerShell 改这个文件

开发过程中我用 PowerShell 的 `Get-Content` / `Set-Content` 对 `index.html` 做过一次批量文本替换，
结果**整个文件被 GBK 代码页往返了一遍**，603 处中文损坏、文件无法编译。

原因很具体：PowerShell 在这个环境下用 **GBK（代码页 936）** 读写文本，而本文件是无 BOM 的 UTF-8。
GBK 是双字节编码，它把 UTF-8 字节流两两配对：

- 配成**合法 GBK 双字节**的，往返后字节不变 → 数据幸存（所以大部分文件其实是完好的）
- 配不成的（`[汉字第 3 字节][后随一个 ≤0x3F 的 ASCII]`），整对塌缩成一个 `?` → 永久丢失 2 字节

事后按字节级取证逆向还原了全部 603 处，但这完全是运气好：损坏模式规整、且原文是我自己写的。

**结论：改这个文件只用两种方式** ——
Node（显式 `utf8`）或支持编码选择的编辑器。用 PowerShell 时至少要显式指定编码：

```powershell
Get-Content -Raw -Encoding utf8 index.html
Set-Content -Encoding utf8NoBOM index.html
```

改完务必跑一次 `node selftest.mjs`，它的第一项就是「脚本语法编译」，第二项校验全部静态 DOM id。
